# Magic World — i18n (7 idiomas)

Sistema de internacionalização adicionado no branch atual. Nenhum breaking change: se você não tocar em nada, o comportamento é idêntico ao anterior (fallback em EN) e o app detecta o idioma do device no primeiro boot.

## O que foi feito

### Infra nova

- **`i18n/`** — sistema de tradução leve, sem `i18next`
  - `types.ts` — shape das traduções (contrato TypeScript)
  - `index.ts` — Zustand store + hook `useT()` + função `t()` cru + detecção via `expo-localization` + fallback pra EN + interpolação `{{param}}` + flag RTL
  - `locales/{en,es,pt,fr,zh,hi,ar}.ts` — 7 idiomas completos, espelhando o shape do EN
- **`components/LanguageSelector/`** — modal para trocar idioma manualmente (bandeira + nome nativo + nome em inglês)

### Idiomas suportados

1. English (en) — 🇬🇧 — source of truth
2. Português (pt) — 🇧🇷 — BR informal (mano/bora)
3. Español (es) — 🇪🇸
4. Français (fr) — 🇫🇷
5. 中文 (zh) — 🇨🇳 — simplificado
6. हिन्दी (hi) — 🇮🇳
7. العربية (ar) — 🇸🇦 — RTL (flag apenas, sem `forceRTL` automático)

### Como usar

**Em componentes:**

```tsx
import { useT } from "@/i18n";

function MyScreen() {
  const { t } = useT();
  return <Text>{t("home.mostWatched")}</Text>;
}
```

**Com interpolação:**

```tsx
<Text>{t("quiz.scoreLine", { correct: 3, total: 5 })}</Text>
// PT: "Você acertou 3 de 5!"
```

**Fora de componentes React (services, Alert):**

```tsx
import { t } from "@/i18n";
Alert.alert(t("paywall.welcomeTitle"), t("paywall.welcomeBody"));
```

**Trocar idioma programaticamente:**

```tsx
const { setLocale } = useT();
await setLocale("pt"); // persiste no AsyncStorage
```

## O que **não** foi tocado (intencional)

- **Corpo dos textos legais** (Privacy Policy, EULA) — só título e botão são traduzidos. Corpo permanece em EN, que é padrão da indústria pra compliance (traduzir texto legal exige revisão jurídica pra cada mercado).
- **Nomes de categorias no Firestore** — o slug (`adventure`, `romance`, etc) permanece em EN pra compatibilidade com o campo `category` dos docs; só o label mostrado ao usuário é traduzido.
- **Conteúdo das histórias, capítulos, opções de branch** — vem do Firestore ou é gerado por IA no idioma da história; o sistema existente com `franc-min` + `translateText` do `services/ai` continua funcionando.
- **Lista de idiomas dentro do menu "Traduzir" da história** — o menu é "traduzir a história PARA outro idioma", então os labels ficam em EN (usuário lê "Spanish" independentemente do idioma da UI).
- **Endless Runner, Spell Storm** — jogos com pouca UI textual visível ao usuário. Se quiser incluir depois, é adicionar as chaves em `i18n/locales/*` e refatorar.
- **`artist: "Magic World"`** no TrackPlayer — é o nome do app.

## Decisões técnicas

### Por que não `i18next`?

- Overhead de ~50KB no bundle para funcionalidade que não usamos
- Não suportamos plurais complexos nem contextos de gênero (pt/es/fr têm gênero mas o texto foi escrito no neutro)
- API custom fica mais simples de estender

### RTL (Arabic)

O árabe é o único locale com `direction: "rtl"` no metadata do store. **Não** chamamos `I18nManager.forceRTL(true)` porque:

1. Exige reload do JS bundle, que quebra qualquer navegação em andamento
2. Nosso layout foi feito pensando em LTR; precisa auditoria dedicada pra espelhar corretamente

A flag está exposta em `useLocaleStore.direction` pra usar quando quiser começar a implementar suporte visual RTL de forma incremental.

### NativeTabs

O `expo-router/unstable-native-tabs` renderiza SwiftUI/Material nativo, que **só lê props no mount inicial**. Sem intervenção, trocar de idioma não atualizava as labels das abas. A solução foi passar `key={locale}` no `<NativeTabs>` — força remount quando o idioma muda. Impacto de UX: durante a troca, o usuário vê um flash rápido de recriação das abas. Aceitável porque a troca é uma ação deliberada.

### Detecção de idioma

Prioridade:
1. Locale salvo no AsyncStorage (`@magic_world_locale`)
2. Primeiro locale do device (`expo-localization.getLocales()`) que bata com um dos 7 suportados
3. Fallback: `en`

Suporta variantes regionais: `pt-BR` e `pt-PT` viram `pt`, `zh-Hans` vira `zh`, etc.

### Fallback em runtime

Se uma chave sumir num locale (bug de tradução), o sistema:
1. Tenta EN como fallback
2. Se EN também não tiver, devolve a própria key (`"profile.foo.bar"`)
3. Emite `console.warn('[i18n] chave ausente: ...')` em `__DEV__`

Isso te ajuda a caçar chaves esquecidas no QA sem crashar o app.
